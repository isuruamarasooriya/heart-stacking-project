# Project 5 – Stacking and Ensembling on the UCI Heart Disease Data

> **Question (written before touching the data):**
> *Does a stacking ensemble of Logistic Regression, Random Forest and an SVM predict heart disease better than the best of those three models used alone?*

Course project: *45 Small Self-learning Projects – A. Modern Tabular ML, Project 5.*
Brief: "Combine 3 models and test if it beats the best single one." Data: Heart disease (UCI).

---

## 1. Problem and baselines

| Step | What it is | Why |
|---|---|---|
| Baseline 1 | Majority-class predictor (`DummyClassifier`) | The floor: any real model must beat "always guess the commonest answer". |
| Baseline 2 | The three single models (Logistic Regression, Random Forest, SVM) | The bar stacking has to clear: **the best one of these, chosen by cross-validation on the training data only.** |
| Challenger | Stacking of those same three models | The thing being tested. |
| Extra reference | Soft voting of the same three models | The *simple* ensemble. Shows whether the learned combination (stacking) is worth more than plain averaging. |

**Primary metric: ROC-AUC** (fixed in `config.yaml` before any result was seen). Accuracy, F1, recall (sensitivity) and precision are also reported. Recall matters here because a missed heart-disease case is more costly than a false alarm.

## 2. Data

* **Source:** UCI Machine Learning Repository, *Heart Disease*, **Cleveland** subset (`processed.cleveland.data`) – <https://archive.ics.uci.edu/dataset/45/heart+disease>
* **Size:** 303 patients, 13 input features, 6 missing values (`ca` and `thal`).
* **Target:** the original `num` (0–4) is converted to **0 = no disease, 1 = disease present** (`num > 0`).
* **Features:** age, sex, chest-pain type (`cp`), resting blood pressure, cholesterol, fasting blood sugar, resting ECG, max heart rate, exercise-induced angina, ST depression (`oldpeak`), ST slope, number of coloured vessels (`ca`), thalassemia result (`thal`).
* The data is public and de-identified; no private records are used.
* The script downloads the file automatically on first run. If you are offline, download it manually and place it at `data/raw/processed.cleveland.data`.

## 3. Method

1. **Split:** stratified 80 / 20 train–test split (seed 42). The test set is not used for any decision.
2. **Preprocessing** (inside every model's `Pipeline`, so it is learned on training folds only – no leakage): median-impute and standardise numeric columns; most-frequent-impute and one-hot encode the categorical codes (`cp`, `restecg`, `slope`, `thal`); pass binary columns through.
3. **Three diverse base models** (deliberately *not* tuned – tuning is a separate project):
   * Logistic Regression (linear)
   * Random Forest, 300 trees (non-linear, tree-based)
   * SVM with RBF kernel (kernel-based). Its probabilities come from Platt scaling (`CalibratedClassifierCV`, sigmoid), because `SVC(probability=True)` is deprecated in scikit-learn 1.9.
4. **Stacking:** `StackingClassifier`. Each base model produces **out-of-fold** probabilities (5-fold inner CV); a logistic-regression **meta-learner** learns how to weigh the three. Out-of-fold predictions are essential – otherwise the meta-learner would see over-confident predictions on rows the base models already memorised.
5. **Selecting the "best single model":** highest mean CV ROC-AUC on the training set among the three singles.

## 4. Evaluation protocol (how the comparison is kept honest)

* **Repeated stratified 5-fold CV × 5 repeats = 25 scores per model**, on the training set. The folds are created **once** so every model is scored on identical folds → differences can be compared pair by pair.
* **Corrected paired t-test** (Nadeau & Bengio, 2003) on those 25 paired differences. CV folds overlap, so a plain t-test is over-confident; the correction widens the uncertainty.
* **Held-out test set scored once** at the end, for all models.
* **Paired bootstrap** (2000 resamples) on the test set gives a 95 % interval for *(stacking − best single)*. With only ~61 test patients, a gain of a point or two is usually inside this interval; the interval makes that visible.
* **Error analysis** of the stacking model's mistakes (see section 6).
* **Reproducibility:** one seed in `config.yaml`; library versions saved to `results/environment.txt`.

## 6. Error analysis and interpretation

The five answers below are written automatically from the real numbers by `run_experiment.py`. Full tables are in **`results/error_analysis.md`** (≥ 10 wrong predictions, most-confident mistakes first, plus error rates by sex, age band and chest-pain type, plus whether the models fail on the same patients).

<!-- INTERPRETATION_START -->
1. **Type of mistake.** The stacking model made 38 out-of-fold mistakes on 242 training patients (15.7%): 24 missed-disease cases (false negatives) and 14 false alarms (false positives), so the mistakes are mostly missed disease. A missed case is the more serious error for a doctor, because a sick patient would be sent home untreated, whereas a false alarm usually only leads to extra tests.

2. **Most confidently wrong patients.** Among the 10 most confident mistakes (model sure at 0.82-0.92), 6 are 'false alarm (false positive)'. The commonest chest-pain type is 'asymptomatic' (6 of 10); 8 are male, and their median age is 59 (all patients: 56). The model was strongly convinced of its wrong answer for these patients, so they are worth inspecting by hand.

3. **Groups.** Looking only at groups with at least 20 patients, the highest error rate is for age band '56-65': 22.1% (21 of 95) versus 15.7% overall; that is about 6 more mistakes than expected (z = 1.7), which is not clearly beyond chance, especially because several groups were compared. Smaller groups are not ranked because their rates are too unstable to trust.

4. **Shared failures.** 34 patients are wrong for both stacking and Logistic Regression; 4 are wrong only for stacking and 5 only for Logistic Regression. About 87% of Logistic Regression's mistakes are also made by stacking, so the models mostly fail on the same patients, which leaves stacking little room to help.

5. **Did stacking beat the best single model?** In cross-validation, Stacking (3 models) was numerically ahead of Logistic Regression on roc_auc (mean difference +0.0033) but the gain is NOT statistically reliable (corrected p = 0.638). On the held-out test set the difference was -0.0032 with a 95% bootstrap interval of [-0.0218, +0.0140], which includes zero, so the test set cannot separate the two models. The difference is too small to be told apart from noise, so the simpler Logistic Regression is the better practical choice: it is cheaper to train and easier to explain.

## 7. Limitations

* **Small data:** 303 patients in total, only ~61 in the test set. One test-set patient changes accuracy by ~1.6 points, so small differences between models are mostly noise.
* **One hospital / one population:** results may not carry over to other clinics, countries or equipment.
* **Binary target:** collapsing severity levels 1–4 into "disease" hides how the models behave on mild vs severe cases.
* **No hyper-parameter tuning:** a tuned single model could change which model is "best", and tuning the stack is a different experiment.
* **Probabilities are not checked for calibration** (see Project 6); the 0.5 threshold is a default, not a clinical choice.
* **Missing values** (6 cells) are imputed with simple rules.
* **Stacking costs more** (5 inner-CV fits of every base model plus a final refit, versus 1 fit for a single model); any gain must be weighed against this extra complexity.
* **Not a medical device.** This is a learning project and must not be used to make clinical decisions.


### Viva cheat-sheet (be ready to explain)

* Why is preprocessing inside the `Pipeline`? → to avoid leakage from the validation fold.
* Why out-of-fold predictions for the meta-learner? → otherwise it trains on over-optimistic base-model outputs.
* Why the same folds for every model? → so scores can be compared pair by pair.
* Why a *corrected* t-test? → CV training sets overlap, so scores are correlated; the plain test is over-confident.
* Why choose the best single model with CV and not the test set? → picking on the test set would leak information and favour the baseline-of-choice.
* Why ROC-AUC as the primary metric? → threshold-free and stable on small data; recall is reported because missed disease is costly.
* Why would stacking *not* help? → if the base models make the same mistakes, or the data is too small for the meta-learner to learn useful weights.
